# 规则目录

检查模式读这个文件。报告违规时引用这里的编号，不凭记忆。每条规则给一个修改前和修改后。

## 文档规则

| 编号 | 规则 |
|---|---|
| D1 | 先分类。程序性文本用祈使句，一句一个动作，每句不超过 30 字。描述性文本用陈述句，每句不超过 50 字，一段一个主题，一段不超过 6 句。逗号分句不超过 40 字。 |
| D2 | 不动代码、命令、路径、报错原文、产品名和事实。原文没有的数字和原因不补。 |
| D3 | 条件在前，动作在后，逗号分隔。 |
| D4 | 用实义动词。不用 进行 / 作出 / 予以 / 加以 / 开展 / 实施 加名词。 |
| D5 | 情态词按阶梯用：必须 / 不得，建议 / 不建议，可以 / 不必，能 / 不能，可能 / 不可能。不用 应该、应当、最好、尽量、务必、宜。可 / 能 / 可能 不互换。 |
| D6 | 主动为主。被字句只在施事真正未知时用。不叠套。无标记被动合法。 |
| D7 | 不用分号。不用破折号连接两个陈述。逗号串起三个以上分句就拆句。 |
| D8 | 一词一义，全文一致。大陆简体术语。 |
| D9 | 概念术语首次出现时定义，不超过 20 字，一句一个。产品名、标准名不定义。 |
| D10 | 只说事实，不说重要性。删空洞词、黑话和「不是 X 而是 Y」。 |
| D11 | 格式为读者服务。不用加粗导语、装饰性加粗、emoji、只管两句话的标题。三项以上才用列表。 |
| D12 | 警告先写命令或条件，再写风险。 |
| D13 | 「的」字链不超过两层。 |
| D14 | -性 / -化 / -度 名词化有更短写法就改回动词或形容词。术语保留。 |
| D15 | 一段内四字格不连用三个以上。 |
| D16 | 中英文之间留一个空格。 |

字数计法：汉字和字母数字各计 1，标点不计，一个行内代码段计 1。句子以 。！？ 为界，括号和引号内的句末标点不断句。30 / 50 / 40 三个数字经 2026-09-09 的基线校准，记录在 `docs/design.md` 第 5 节。

## 回复规则

| 编号 | 规则 |
|---|---|
| R1 | 只用散文。不用标题、列表、加粗、表格。读者要复制的内容才用代码块。 |
| R2 | 最多 5 句。列表项和冒号引出的分点都算句。 |
| R3 | 第一句给答案。不复述问题。 |
| R4 | 不用破折号。 |
| R5 | 概念术语第一次出现时用几个字解释。产品名不解释。 |
| R6 | 不用开场白和结束语。 |
| R7 | 报错原文、安全警告、破坏性操作前的确认，不缩短。 |

## 各类文档的结构

报错文本：发生了什么（简单过去），已知原因，修复的命令或条件。不写「哎呀」「出错了」「请稍后再试」。

> 连接数据库失败：用户 `app` 的密码不正确。设置 `DB_PASSWORD` 后重新连接。

操作手册：每步一个祈使句，条件在前，警告放在有风险的那一步之前。读者在深夜按着做，每句只读一遍。

故障排查：先写可观察的现象，再写要收集的日志和错误码，再按证据价值和风险排检查顺序，每项检查写判断条件。原因只有证据支持时才写。

事故报告：只用简单过去。写时间、影响范围、原因、恢复动作、后续措施。不写「我们已经注意到」「可能影响了部分用户」「深表歉意」。

> 14:02 到 14:31 UTC，12% 的 API 请求返回 HTTP 502。14:00 的一次发布删除了缓存预热步骤，缓存节点过载。14:27 回滚。14:31 起全部请求正常。本周把预热检查加进发布流程。

发布说明：一条一个变更，一句话。破坏性变更按警告的结构写，先命令后说明。

> 破坏性变更：把 `/v2/users` 的调用改成读 `first_name` 和 `last_name`。`name` 字段在 2026-10-01 后返回空。

提交信息和 PR 描述：标题祈使句，正文陈述句，每句不超过 45 字。删掉「本 PR 旨在」。

给模型的指令（系统提示、AGENTS.md、skill）：程序性文本。一句一个指令，条件在前，不用「应该」，模型会把「应该」读成可选。

## AI 腔

主要规则已经覆盖了中文 AI 输出最常见的特征。下面是 lieflat 语料（629 篇，2,826,972 字，语料不公开，数字第三方无法核验）里倍率最高的几项，按 AI 频率除以人类频率：

| 特征 | 倍率 | 对应规则 |
|---|---:|---|
| 冒号空转引列表（「几种场景：」） | 9.4 | D11、R1 |
| 拟人化喻体 | 7.3 | D10 |
| 段首零主语评论 | 4.4 | D6，补上主语或「这」 |
| 提示语冒号（「核心是：」） | 3.8 | D11 |
| 不是 X 而是 Y | 3.4 | D10 |
| 起手式「说白了」 | 3.2 | D10 |
| 序数词当小标题 | 3.1 | D11 |
| 破折号 | 3.0（Claude 4.25，DeepSeek 5.16，GPT 0.11） | D7、R4 |
| 相邻句同构 | 2.0 | D15 |

同一语料证明下面这些不是 AI 特征，不要为了去 AI 味改它们：句长均匀（无差异）、被字句（无差异）、动词名词化（人类更多）、正文问句（人类多 17 倍）、比喻本身（人类多 2.4 倍）、句内排比（人类更多）。D6 和 D14 管的是欧化中文，不是 AI 味。

中文维基百科《AI 生成文的特征》另外列了：稳稳地、作为 / 服务于、见证、标志着、代表转变、根植于、不可磨灭，以及「你希望」「当然可以」「希望这对你有帮助」这类协作腔。
